# 小学数学体系化掌握树设计

## 1. 目标与边界

本功能帮助家长判断孩子是否真正形成了人教版小学数学的完整知识体系，而不是只展示文档实体关系或让用户手工点亮节点。

第一阶段范围固定为：

- 人教版小学数学一至六年级、上下册共 12 册教材；
- 2026 春一至六年级下册人教版《学霸提优大试卷》；
- 2026 秋一至六年级上册人教版《五星学霸》数学；
- 教材/试卷向量化、Wiki/Neo4j 图谱、课程先修图、诊断作答证据和掌握度展示；
- 本地自托管 WeKnora，不把教材或试卷原文提交到 Git。

语文、英语等其他人教学科不在第一阶段导入，但数据结构必须能在后续复用。

## 2. 已验证事实

- WeKnora 已具备 OpenAI 兼容模型、文件导入、1024 维 pgvector、Wiki、Neo4j GraphRAG 和知识图谱前端。
- DashScope `qwen3.7-plus` 已通过真实聊天请求；用于知识抽取、题目归类、诊断解释和问答。
- DashScope `qwen3.7-text-embedding` 对当前密钥返回 `Model.AccessDenied`，不能使用。
- DashScope `text-embedding-v4` 已通过真实请求并返回 1024 维向量；用于全部教材与试卷向量化。
- `/Volumes/extdownload01/ChinaTextbook/小学/数学/人教版` 中 12 册教材齐全。
- 当前素材目录中含 179 个“学霸提优大试卷”相关文件、520 个“五星学霸”相关文件，但没有任何路径命中 `26春`、`2026春`、`26秋` 或 `2026秋`。系统必须明确显示指定版本“缺失”，不得静默替换为 2025 或其他版本。
- 参考页 `https://panpanspace.com/math/` 使用暗色分层科技树、彩色领域节点、SVG 贝塞尔依赖线、locked/available/completed 三态、进度条、前置提示和本地进度。

## 3. 方案选择

### 方案 A：直接复用 Wiki 图谱

实现最少，但 Wiki/GraphRAG 表达的是文档实体关系，不能回答“孩子是否掌握”“证据是否充足”“哪个先修薄弱点阻塞下游”。不采用。

### 方案 B：独立学习平台

产品自由度高，但会重复 WeKnora 已有的模型管理、导入、检索、权限、任务队列与图谱基础设施。不采用。

### 方案 C：WeKnora 核心 + 数学掌握树领域层

保留 WeKnora 的知识库、向量化、Wiki 与 Neo4j；增加课程节点、先修关系、题目映射、诊断尝试和掌握证据。采用此方案。

用户已明确授权在既定方向内自主迭代，因此方案 C 作为实施默认，不为同一范围重复请求确认。

## 4. 产品信息架构

知识库详情新增“掌握树”入口，仅当知识库启用了数学课程包时显示。

主视图由以下区域组成：

1. 顶部概览：体系覆盖率、已稳固知识点、待验证知识点、关键薄弱链和素材完整度。
2. 筛选区：年级、上下册、知识领域、掌握状态、仅看阻塞链。
3. 科技树：六个年级层从低到高排列；节点按数与运算、数量关系、图形与几何、统计与概率、综合实践等领域着色；跨年级先修关系用 SVG 依赖线连接。
4. 节点状态：`untested`（未测）、`weak`（薄弱）、`developing`（形成中）、`mastered`（稳固）。可学习性与掌握度分开，不能仅因前置节点通过就把当前节点标为已掌握。
5. 节点详情抽屉：展示先修/后继、教材证据、试卷证据、最近作答、错误类型、置信度和“开始诊断”。
6. 素材状态：12 册教材与 2026 春秋试卷分别显示已发现、已上传、向量化中、图谱中、完成、失败或缺失。

参考站点的视觉语言可以借鉴，但不复制其源码、文案、节点数据或教材内容。

## 5. 数据模型

### 5.1 课程结构

`math_curriculum_nodes`

- `id`：稳定业务 ID，例如 `rj-g3-s2-fractions-basic`；
- `knowledge_base_id`：所属知识库；
- `parent_id`：年级/册次/单元层级；
- `node_type`：`stage | grade | term | unit | concept`；
- `grade`、`term`、`domain`、`title`、`summary`、`sort_order`；
- `expected_question_count`：达到可诊断所需题量；
- `metadata`：教材版本、课程标准标签等扩展字段。

`math_curriculum_edges`

- `from_node_id`、`to_node_id`；
- `relation_type`：首版仅 `prerequisite`，后续可扩展 `part_of | similar | transfer`；
- `strength` 和 `rationale`，用于解释依赖关系。

### 5.2 素材与题目证据

`math_source_bindings`

- 将课程节点绑定到 WeKnora 的 `knowledge_id`、可选 `chunk_id`；
- `source_type`：`textbook | exam | answer_key`；
- `edition`、`school_year`、`season`、`grade`、`term`、`page_from/page_to`；
- `content_hash` 防止重复导入；
- 仓库只保存元数据结构，不保存受版权保护的 PDF 或题目正文。

`math_questions`

- `id`、`source_binding_id`、`question_locator`、`question_type`、`difficulty`；
- `primary_node_id` 与多对多知识点映射；
- `answer_locator`、`scoring_rule`、`extraction_confidence`；
- 正文保留在本地数据库/知识块中，不进入 Git fixture。

### 5.3 诊断与掌握度

`math_diagnostic_attempts`、`math_diagnostic_responses`、`math_mastery_evidence`

- 一次诊断包含目标范围、选题快照、开始/结束时间；
- 每道作答记录正确性、耗时、自评置信、错误类型和关联知识点；
- 每条掌握证据可追溯到题目、作答和评分规则；
- 孩子身份第一阶段用本地 profile，不收集不必要的实名或敏感信息。

掌握度首版采用可解释的加权证据模型：

- 基础题、变式题、综合题分别计不同权重；
- 猜对、自评低置信或明显超时会降低证据权重；
- `mastered` 至少需要 3 道独立题、覆盖 2 种题型，并在最近两次诊断中表现稳定；
- 只有一次作答时最多为 `developing`；
- 先修节点薄弱会产生“体系风险”，但不会篡改当前节点的真实作答分数；
- 所有状态同时输出 `score`、`confidence`、`evidence_count` 和原因。

## 6. 数据流

1. 素材扫描器读取允许目录，只生成 manifest、哈希和版本判定，不复制文件到仓库。
2. 导入器创建/复用“人教版小学数学”知识库，上传 12 册教材和已确认的目标试卷。
3. WeKnora DocReader 解析 PDF；`text-embedding-v4` 以 1024 维生成向量。
4. `qwen3.7-plus` 执行章节/概念/题目抽取；开启 GraphRAG 与 Wiki 生成。
5. 课程构建器把教材目录和抽取结果规范化为课程节点，先修边由规则模板和 LLM 建议共同产生；低置信边进入待审，不自动进入正式图。
6. 题目映射器把试卷题定位到课程节点，保留来源和置信度。
7. 诊断服务按未测、低置信和关键阻塞节点选题，提交作答后更新证据与掌握状态。
8. 前端科技树读取领域 API，展示覆盖率、依赖、素材与诊断证据。

## 7. 模型与安全配置

- Chat/Extraction：`qwen3.7-plus`，OpenAI compatible provider；
- Embedding：`text-embedding-v4`，1024 维，OpenAI compatible provider；
- Base URL：`https://dashscope.aliyuncs.com/compatible-mode/v1`；
- API Key 只存在于被 Git 忽略的 `.env` 或本机钥匙串，不进入源码、测试快照、日志或提交；
- `SYSTEM_AES_KEY` 必须配置为 32 字节，用于 WeKnora 数据库中的模型凭据加密；
- `NEO4J_ENABLE=true`，使用 Compose 的 `neo4j` profile；
- 不启用原始 LLM 流转储，避免把教材与题目内容写入调试日志。

## 8. 错误处理与幂等性

- 扫描结果按绝对路径、大小、mtime 和 SHA-256 生成稳定条目；重复运行不重复上传。
- 版本不匹配或目标文件缺失时标记 `missing`，不降级到旧版。
- 上传、解析、向量化、图谱和课程映射分阶段记录；单文件失败可重试，不回滚其他成功文件。
- 模型测试在导入前执行；聊天或嵌入任一不可用时停止批量导入。
- 低置信概念、先修边和题目映射保留待审状态，不能伪装成确定知识。
- 删除或重置诊断数据必须与知识素材导入分离，避免误删知识库。

## 9. 测试与验收

### 自动测试

- Go：课程节点 DAG 校验、循环检测、素材幂等、掌握度边界、API 权限和迁移测试；
- 前端：节点状态、筛选、进度统计、抽屉、依赖线数据转换、空/缺失/失败态测试；
- 导入器：12 册教材发现、错误版本拒绝、重复文件去重、断点续传和模型预检；
- 端到端：创建知识库、导入小样本、完成向量化/图谱、读取掌握树、提交一轮诊断、查看状态变化。

### 数据验收

- 教材 manifest 必须为 12/12；
- 指定试卷在素材未到齐时明确为 0/目标数，不以旧版凑数；
- 每个正式概念必须至少绑定一个教材证据；
- 正式先修图必须无环；
- 题目映射必须带来源、页/题定位和置信度；
- 随机抽检至少 30 个概念和 60 道题，记录准确率，不达阈值继续迭代。

### 产品验收

- 家长能在 30 秒内看出“已稳固、未测、薄弱、被哪些先修阻塞”；
- 每个掌握结论可追溯到具体作答与教材/试卷来源；
- 不能通过手工点星直接伪造掌握；
- 手机与桌面均可阅读，依赖线不遮挡节点，减少动态效果模式可用。

## 10. 八小时自主迭代循环

1. 第 1 阶段：启动基础设施、模型配置、素材 manifest 和最小导入；
2. 第 2 阶段：领域数据模型、课程 DAG 与 API；
3. 第 3 阶段：参考科技树视觉、节点抽屉与状态说明；
4. 第 4 阶段：题目映射和诊断掌握度最小闭环；
5. 后续循环：测试失败、数据抽检、浏览器 QA、性能与可访问性问题按风险排序逐轮修复；
6. 每轮保留可运行状态和验证记录，最终再推送到用户 fork。

若指定 2026 试卷在八小时内仍未出现在素材目录，仍完成教材、模型、图谱、课程树和诊断骨架，并把试卷导入保持为可续跑的明确缺口，而不是阻塞全部交付。
